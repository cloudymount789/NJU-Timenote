# NJU Timenote Backend API

This document describes the future backend contract for the Flutter app. The current app uses mock repositories with the same domain shape, so replacing the mock layer should not require screen changes.

## Conventions

- Base URL: `/api/v1`
- Content type: `application/json`
- Timestamps: ISO 8601 strings with timezone
- IDs: opaque strings generated by the backend
- Authentication: not implemented in the current prototype; add an `Authorization` header in a future authenticated version.

Error response:

```json
{
  "error": {
    "code": "validation_error",
    "message": "course name is required"
  }
}
```

## Courses

### GET `/courses?week=6`

Returns courses that occur in the requested teaching week.

Response:

```json

    {
      "id": "course-1",
      "name": "微积分 II",
      "teacher": "",

      "note": "",
      "dayOfWeek": 1,
      "startPeriod": 1,
      "endPeriod": 2,
      "weekRule": "all",
      "startWeek": 1,
      "endWeek": 16,
      "colorKey": "purple",
      "source": "sample",
      "createdAt": "2026-04-01T00:00:00+08:00",
      "updatedAt": "2026-04-01T00:00:00+08:00"
    }
```

### POST `/courses`

Creates a manual course.

Request:

```json
{
  "name": "软件工程",
  "teacher": "陈老师",
  "location": "仙林 B406",
  "note": "小组项目",
  "dayOfWeek": 5,
  "startPeriod": 3,
  "endPeriod": 4,
  "weekRule": "all",
  "startWeek": 1,
  "endWeek": 16
}
```

Response: `201 Created`

```json
{
  "data": {
    "id": "course-100",
    "name": "软件工程",
    "teacher": "陈老师",
    "location": "仙林 B406",
    "note": "小组项目",
    "dayOfWeek": 5,
    "startPeriod": 3,
    "endPeriod": 4,
    "weekRule": "all",
    "startWeek": 1,
    "endWeek": 16,
    "colorKey": "blue",

    "createdAt": "2026-04-09T09:41:00+08:00",
    "updatedAt": "2026-04-09T09:41:00+08:00"

```

### DELETE `/courses/{courseId}`

Deletes a course permanently.

Response: `204 No Content`

## Todos

### GET `/todos`

Returns todo items.

Optional filters:

- `hasDeadline=true`
- `status=open`

Response:

```json
{
  "data": [
    {
      "id": "todo-1",
      "title": "数据结构实验报告",
      "note": "实验三",
      "dueAt": "2026-04-09T23:59:00+08:00",
      "status": "open",
      "hasDeadline": true,
      "createdAt": "2026-04-09T09:41:00+08:00",
      "updatedAt": "2026-04-09T09:41:00+08:00"
    }
  ]
}
```

### GET `/todos/search?q=数据结构`

Searches todo titles and notes.

Response uses the same shape as `GET /todos`.

## Settings And Data

### GET `/settings/semester`

Response:

```json
{
  "data": {
    "semesterStartDate": "2026-09-01"
  }
}
```

### GET `/settings/periods`

Response:

```json
{
  "data": [
    { "period": 1, "start": "08:00", "end": "08:50" },
    { "period": 2, "start": "09:00", "end": "09:50" }
  ]
}
```

### POST `/settings/backup`

Starts a local-backup-compatible export job.

Response:

```json
{
  "data": {
    "backupId": "backup-1",
    "status": "completed"
  }
}
```

### POST `/exports`

Creates a shareable export.

Response:

```json
{
  "data": {
    "exportId": "export-1",
    "status": "completed",
    "downloadUrl": "https://example.com/export-1.zip"
  }
}
```

## Flutter Repository Mapping

| Flutter interface | Method | HTTP endpoint |
| --- | --- | --- |
| `CourseRepository` | `fetchCourses(week)` | `GET /courses?week={week}` |
| `CourseRepository` | `addCourse(draft)` | `POST /courses` |
| `CourseRepository` | `deleteCourse(courseId)` | `DELETE /courses/{courseId}` |
| `CourseRepository` | `importCoursesFromScreenshot()` | `POST /courses/imports/screenshot` |
| `TodoRepository` | `fetchTodos(hasDeadline, query)` | `GET /todos`, `GET /todos/search` |
| `SettingsRepository` | `fetchSemesterSettings()` | `GET /settings/semester`, `GET /settings/periods` |
| `SettingsRepository` | `backup()` | `POST /settings/backup` |
| `SettingsRepository` | `exportData()` | `POST /exports` |

The current Flutter app ships only mock implementations. A real backend integration should add HTTP-backed repository classes that implement the same interfaces and preserve the screen-facing method contracts.
